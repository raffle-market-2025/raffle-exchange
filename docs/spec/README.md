Версия 1.3 • 28 октября 2026 • отдельный модуль текущего проекта Raffle Market.

## Ключевое ограничение реализации

Публичный Walt P2P API используется для чтения рынка. По решению заказчика торговое исполнение проектируется через веб-интерфейс Walt: отдельный браузерный worker работает в собственной авторизованной сессии мерчанта. Отдельный торговый API не требуется для выбранной архитектуры. Фактические возможности интерфейса, устойчивость восстановления и ограничения сессии проверяются до реальных расходов. Поддержка и допустимость такой автоматизации со стороны Walt не подтверждены; возможное ограничение аккаунта учитывается как риск, а не скрывается.

Гривневая сторона: только Ощад, сейчас через веб-форму; клиент присылает скрин оплаты в Walt, банк присылает push, баланс карты можно читать в форме. Скрин — вспомогательное свидетельство, не самостоятельное подтверждение зачисления. Наличие банковского API не предполагается. Требуемые личные подтверждения учитываются как отдельные задачи, а не объявляются автоматическими.

Рекламный блок после сделки предусмотрен в собственном боте или интерфейсе Raffle. В чат и объявления Walt его отправлять нельзя по действующим правилам. Если Walt когда-либо официально разрешит иной канал, это оформляется новой версией интеграции; настройки не обходят этот запрет.

## Принятые проектные решения

- Первая пара — USDT ↔ UAH. Банковский USD и любые другие пары исключены из области задания по уточнению заказчика.
- Никакого автоматического перевода средств в TON, покупки билета или регистрации в промо вместе с обменом.
- Торговые средства, призовой резерв и средства участников розыгрышей разделены.
- Рабочая сеть проекта — Mainnet. Локальные модели и повторы обезличенных событий используются для проверки; обязательного Testnet-этапа нет.
- Подключение реальных денег не входит в изготовление этого ТЗ и требует отдельного решения о счетах, лимитах и доступах.
- Публичные тексты используют обозначение «Оператор». Неподтверждённые реквизиты и обещания не добавляются.

Готовность: повторный сквозной аудит требований выполнен, исправления внесены в v1.3. Торговый API не является зависимостью. Исполнение через веб, банковские доказательства и связь с собственным рекламным каналом ещё требуют фактической проверки. Это аудит ТЗ, не работающего кода.

Первый этап обслуживает заявки, пришедшие в Walt к нашему мерчанту; собственная клиентская форма обмена — последующий необязательный этап. Порядок применения требований: сквозной контракт 08 определяет обязательные инварианты; специализированные документы 06 и 07 — адаптеры; документ 03 — промо; остальные документы — общие требования. Новая возможность провайдера не подразумевается без наблюдения.
