# ADR-0001. Отдельная БД обмена

Статус: **принято** в части изоляции; выбор провайдера **открыт** и закрывается на гейте G1 вместе с ADR-0004.

## Контекст

ТЗ требует отдельных секретов, баланса и учёта обменника и запрещает влияние сбоев обмена на розыгрыши (EX-039). Техническое ТЗ говорит об «отдельной схеме `exchange`» (02 §10), основное — о «собственной схеме Postgres/Neon» (EX-040). План репозиториев предполагает отдельную БД.

## Решение

1. Отдельная база PostgreSQL 16 `raffle_exchange`; все таблицы обмена — в схеме `exchange` внутри неё. Это строже обеих формулировок ТЗ и совместимо с ними.
2. Ни общих таблиц, ни общих учётных данных с базами `raffle-backend-next` и `raffle-admin-next`. Raffle получает данные обмена только через API (`exchange-api`), никогда не читает базу обмена напрямую.
3. Время хранится в `timestamptz`, сессия БД в UTC. Суммы — `numeric` с явным масштабом по активу; `float`/`double` запрещены.
4. Локально — контейнер из `docker-compose.yml` на порту 5433, чтобы не пересекаться с базами розыгрышей.

## Открытый вопрос: провайдер

| Вариант | Плюсы | Минусы и условия |
|---|---|---|
| Управляемый Postgres (Neon, Supabase или другой) | PITR и бэкапы у провайдера | Worker обязан ходить по прямому соединению, не через pooler в transaction mode: `FOR UPDATE SKIP LOCKED` в длинной транзакции, advisory locks и `LISTEN/NOTIFY` там ломаются. Scale-to-zero выключить: постоянный опрос outbox держит вычислитель активным, и это стоимость |
| Postgres на том же хосте, что и сервисы | Минимальная задержка, полный контроль | Бэкапы, PITR, обновления и мониторинг — на нас; учение по восстановлению (R-10) обязательно |

Рекомендация: управляемый Postgres с PITR в том же регионе, что и хост ADR-0004, прямое соединение для worker. Окончательно — вместе с выбором хоста.

## Последствия

- В ТЗ EX-040 стоит заменить «Postgres/Neon» на «отдельная БД PostgreSQL, провайдер по ADR-0001».
- Резервная копия старше внешних операций восстанавливается только через сверку (02 §12): это требование к процедуре восстановления независимо от провайдера.
